# DESIGN_GROWTH_TREE.md — 局外成长树设计（三轨）

> **状态**：设计稿（2026-09-04 起草，供评审，未实施）
> **目标**：把「碎片带回基地 → 变强」从「一次性买断 8 节点 + 临时献祭」升级为
> **可持续成长 + 每局主动配置**的完整局外引擎；与现有 meta.js / base.js 接口贴合，
> 不推翻已有系统。
> **前置阅读**：`docs/PRODUCTION_ROADMAP.md`（四层框架，本设计归入 Replayability /
> 局外层）、`js/meta.js`（现有 UPGRADES / MILESTONES / 事务接口）。

| 已有 | 说明 |
|---|---|

**缺口**：① 升级买满后碎片只剩临时献祭一个出口，缺「长期目标」；② 没有「每局下潜前的
主动配置决策」（选什么、赌什么）；③ 碎片经济缺乏「高风险高回报」通道。

## 1. 设计总览：三轨成长

```
                ┌─────────────────────────────────────────────┐
                │        回 基 地（碎片结算）                   │
                └────────────────────┬────────────────────────┘
                                     ▼
   轨道 A  基建升级（永久）── 医疗站/武器仓库/弹药/档案室/训练场 + 新增 2 项
                                     │
   轨道 B  共鸣等级（可重复投入）── 弹药亲和/寻宝本能/老兵直觉/深渊亲和，各 5 级
                                     │
   轨道 C  准备桌（每局主动配置）── 深渊核心：基础献祭 + 祝福池 + 血契
                                     │
                                     ▼
            下 潜（startRun 应用全部乘区）→ 地牢 → 结算 → 回基地
```

- **轨道 A**：一次买断、长期永久 —— 已有，只做小扩展。
- **轨道 B**：**碎片日常出口**，重复投入、价格指数递增，制造「攒碎片 → 变强」的长期目标。
- **轨道 C**：**每局决策**，碎片换本局优势（或赌风险），制造「这局我该怎么配」的取舍。

三条轨道共享同一碎片池，形成天然取舍：**这碎片是攒着点永久，还是这局梭哈？**

## 2. 轨道 A：基建升级（扩展现有 UPGRADES）

维持现有 5 项不动（不破坏存档与面板），新增 2 项补空白：

| key | 名称 | 级数 | 价格 | 每级效果 |
|---|---|---|---|---|
| `armor` | 装甲舱 | 1 | 45 | 开局护甲 +1 |
| `magnet` | 重力靴 | 2 | 35 / 60 | 每级拾取半径 +30%（弹壳/钥匙/碎片/血量） |

→ 总节点 8 → **11**。改动面：`meta.js` UPGRADES 表 + `game.js` startRun 两处应用 +
基地面板自动渲染（现有 buyUpgrade 面板已通用，无需新 UI）。

## 3. 轨道 B：共鸣等级（核心新增，碎片长期出口）

**概念**：深渊共鸣 RANK——玩家对「破晓引擎」持续注入碎片，提升对深渊的亲和力。
每项 5 级封顶，**价格递增**（第 n 级 = base × (1+n)×0.5 取整），总投入量级约 400~600 碎片，
是「几十局都点不完」的长期目标，避免速满。

| id | 名称 | 每级效果 | 价格序列 |
|---|---|---|---|
| `affinity_ammo` | 弹药亲和 | 全武器弹匣 +8% 且装填 -4% | 15 / 25 / 40 / 60 / 85 |
| `affinity_loot` | 寻宝本能 | 特殊房概率 +4%、宝箱高品质 +1 档概率 | 15 / 25 / 40 / 60 / 85 |
| `affinity_vet` | 老兵直觉 | 翻滚冷却 -5%、受击无敌帧 +5% | 12 / 20 / 32 / 50 / 70 |
| `affinity_shard` | 深渊亲和 | 深渊碎片拾取值 +10% | 18 / 30 / 48 / 72 / 100 |

**实现**：`meta.js` 新增 `RESONANCE` 定义表 + `data.resonance[id]=lv` + `buyResonance(id)`
事务（复用 `upgradePrice` 模式，价格序列数组）。`game.js startRun` 应用乘区：
- 弹匣：`def.mag` 生成时乘 `1+0.08*lv`（或折算到弹药效率）
- 装填：`reloadMul *= 0.96^lv`
- 特殊房概率：gen 里加概率
- 翻滚 CD / 无敌帧：player 初始化乘区
- 碎片拾取：拾取时乘 `1+0.10*lv`

**UI**：深渊核心「破晓引擎」面板新增「共鸣」页（与轨道 C 同一入口）。

## 4. 轨道 C：准备桌（每局主动配置，深化深渊核心）

把深渊核心从「单一 +15% 献祭」升级为 **准备桌**：交互打开后三个页签 ——
**基础献祭 / 祝福 / 血契**。祝福与血契为**本局临时**，下潜结算后清空。

### 4.1 基础献祭（保留现有）
8 碎片 → 本局全伤害 +15%，可叠（×1.15^N）。作为「无脑稳定选项」保留。

### 4.2 祝福池（每局随机出 3 个，多选可叠加，价格固定）
| id | 名称 | 价格 | 本局效果 |
|---|---|---|---|
| `boon_steel` | 钢骨 | 12 | 护甲 +1 |
| `boon_rage` | 狂热 | 15 | 攻速 +12% |
| `boon_wind` | 疾风 | 10 | 移速 +10% |
| `boon_greed` | 贪婪 | 15 | 碎片拾取 +30%（滚雪球） |
| `boon_luck` | 好运 | 14 | 全掉落品质 +1 档概率 |
| `boon_regen` | 再生 | 16 | 每层回 1 颗红心 |

### 4.3 血契（高风险高回报，本局）
| id | 名称 | 价格 | 本局效果 |
|---|---|---|---|
| `pact_blood` | 血之契约 | 18 | 全伤害 +40%，但生命上限 -2 |
| `pact_glass` | 玻璃大炮 | 20 | 全伤害 +70%，但受到伤害 +50% |
| `pact_fast` | 赌命狂奔 | 16 | 攻速 +30% 且移速 +15%，但翻滚冷却 +30% |

### 4.4 规则
- 祝福/血契**每局开局前选购**，最多可带 2 个（制造取舍：钢骨 + 狂热，还是梭哈血契？）。
- 结算（死亡/胜利）时本局所带祝福/血契**清空**，碎片永久项不受影响。
- 与轨道 B 叠加不冲突（B 是永久乘区，C 是本局乘区）。

**实现**：`meta.js` 新增 `BOONS` / `PACT` 定义表 + `data.runBoons[]`（本局临时，开局生成、
结算清空）+ `buyBoon(id)` 事务（扣碎片，写入 runBoons）。`startRun()` 应用。
`base.js` 核心交互从单按钮「献祭」扩展为三页签面板。

## 6. 数值平衡原则

1. **永久项每级收益小且稳定**（弹匣/装填/拾取），不破坏单局平衡。
2. **共鸣价格指数递增**，总量级 400~600 碎片 →「几十局点不完」，防速满、有长线目标。
3. **祝福单局强但消耗碎片**，与永久项竞争同一碎片池 → 每次下潜都做取舍。
4. **血契收益高但代价明确** → 给熟练玩家「赌一把」的通道，不强加。
5. 全部走**乘区**，不与现有词缀/武器/祝福硬编码冲突。
