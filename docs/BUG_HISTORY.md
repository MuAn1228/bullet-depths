## FIX-001 · 25 秒保底清敌误清慢节奏战斗中的敌人 【证据 A】

**问题**
曾经的清剿逻辑带有「房间锁定超过 25 秒就自动清空剩余敌人」的保底机制。

**后果**
玩家绕后打盾卫、躲避图腾激光、等狙击手瞄准间隙时，敌人在眼前凭空消失，
慢节奏战斗被彻底摧毁。

**当前解法**
整房超时清场**被彻底移除**，改为：
```js
// game.js:180-182
// 残敌提醒：长时间未清剿时周期性提示剩余数量（仅提示，绝不自动清除）。
// 反软锁由敌人系统的"位置非法 0.8 秒自愈"负责（只处理卡墙敌人），
// 不做整房超时清空——避免慢节奏战斗（绕后盾卫/躲避激光）中敌人凭空消失。
```

**回归测试**
自测步骤 `25_慢节奏战斗不误清`（`main.js:702-706`）：
```js
// 挂机 35 秒（超过旧版 25 秒超时阈值）：敌人不应被系统自动清除
assert(sentinel.dead===false,'哨兵敌人被超时机制误清除（慢节奏战斗清场回归）');
assert(combat.locked===true,'挂机后房间被误清剿/门被误开');
```
配套 `25b_卡墙敌人自动消灭`（`main.js:731-739`）验证替代方案有效且不误杀正常敌人。

**为什么不能改回去**
见 `HIGH_RISK_AREAS.md` 的 H1。

## FIX-002 · 盾卫无法从正面击破，只能绕背 【证据 A】

**问题**
盾卫（shield）正面格挡过于绝对，普通武器无法从正面造成任何伤害，
战斗力弱的武器持有者只能绕背，体验很差。

**当前解法**
连续（实为累计）格挡 5 次后进入 `guardbreak` 状态 2.5 秒。
```js
// enemies.js:206
// 破防：连续格挡 5 次盾牌被震开，踉跄 2.5 秒（不格挡/不转身/不攻击），
// 普通武器的输出窗口
```
同时把盾卫转向速率压到 2.6 rad/s（其他敌人 5），使绕背可行：
```js
// enemies.js:354-355
// 盾卫转身极慢（2.6/s）：绕背走位可行；其他敌人正常转向
```

**回归测试**
自测步骤 `26_盾卫格挡与破防`（`main.js:744-784`）验证六项：
4 连格挡不破防 / 第 5 次破防 / 破防窗口正面直击掉血 / 破防后恢复格挡 / 背面正常扣血 / 爆炸无视格挡。

**注意**
注释写"连续"，但 `guardHits` 只在满 5 时清零、无超时衰减 → 实际是**累计**。

## FIX-019 · 玩家无法对 Boss 造成任何伤害（原 BUG-001，P0）【证据 A】

**问题**
`weapons.js` 中 5 处 Boss 伤害判定把**模块对象 `G.boss`** 当成 Boss 实例用。
`G.boss = B`（`boss.js`），`B = { active, spawn(), update(), hurt(), clear() }`，
实例在 `G.boss.active` 上 → `G.boss.x/.z/.r/.spawnT` 全是 `undefined` → 距离为 `NaN`
→ 子弹/爆炸/环绕刃/电弧链/追踪弹**全部打不到 Boss**，正常游戏无法通关。

**为什么曾长期漏网**
自测步骤 17 是直接调 `G.hurtBoss()` 推进 Boss 战的，**完全绕开了武器系统**，
39 步全绿但真实链路是断的。

**当前解法**
5 处统一改为先取实例再判定（`weapons.js`，2026-09-01）：
```js
const boss = G.boss && G.boss.active;
if(boss && !boss.dead && ...){ ... G.hurtBoss(...) }
```
覆盖：电弧链选目标 / 爆炸伤害 / 环绕刃碰撞 / 追踪弹选目标 / 常规子弹碰撞。

**回归测试**
新增步骤 `35_Boss可被真实子弹与爆炸伤害`（`main.js`，2026-09-01）：
- 在房间内找 3 格空地，`G.boss.spawn()` 生成 Boss，清空残留敌人后
  发一颗**真实子弹**（走 `W.update` 完整碰撞链路）断言掉血；再 `W.explode` 断言掉血
- ⚠️ 写此测试的坑：Boss 处于 `intro`（出场演出）状态时 `B.hurt` **直接免伤**，
  测试必须把状态置为 `cool`，否则会误判修复无效

**为什么不能改回去**

## FIX-022 · 道具推挤后不回检墙体，实体可能被挤进墙里（原 BUG-005）【证据 A】

**问题**

const bad = G.solidForMove(e.x,e.z) || G.solidForMove(e.x+m,e.z) || ...

## FIX-024 · 瞄准射线 NaN 地雷：开局首帧鼠标在屏幕正中心会永久毁掉相机与角色朝向 【证据 A】

**问题**
`game.js` `updateCamera` 的鼠标→世界射线与 y=0.55 平面求交用
`t=(0.55-ray.origin.y)/ray.direction.y`。相机未俯视时（开局第 1 帧，相机还在原点、
水平朝向），屏幕**正中心**像素的射线 `direction.y=0` → `t=Infinity` →
`ray.origin.x + ray.direction.x*Infinity = 0*Infinity = NaN`。
NaN 写入 `G.input.aimX` → `tx=NaN` → `camX=lerp(0,NaN,…)=NaN` →
`camera.position.set(NaN,…)` → 相机矩阵永久 NaN → 之后每一帧射线全是 NaN
（`t>0` 恒 false，aim 永不恢复），角色 `face` 随之永久 NaN。
**触发条件**：开局后第一次 `updateCamera` 时鼠标恰好停在屏幕正中心像素（低频但必现）。

**当前解法**（`game.js` `updateCamera`，2026-09-01）
```js
// isFinite 守卫：相机未俯视时射线可能平行地面（direction.y=0 → t=Infinity），
// 0*Infinity=NaN 会永久污染 camX/相机矩阵/角色朝向，必须跳过本帧更新
if(t>0 && isFinite(t)){ ... }
```

**回归测试**
步骤 `39_角色朝向系统回归`（`main.js`，2026-09-01）第 ③ 段：
把相机强制置回原点水平朝向、鼠标置屏幕正中心，跑一次 `updateCamera`，
断言 `camX/camZ`、`aimX/aimZ`、`p.mesh.rotation.y` 全部保持有限值。

**为什么不能改回去**
角色朝向系统（`player.js` 的 `p.face`）直接消费 `G.input.aimX/aimZ`，
任何一帧 NaN 都会通过 `G.angLerp` 永久滞留，无自愈路径。

## FIX-025 · STEP12 自测 flake：弹道上的爆炸桶被暴击打爆，炸伤翻倒的桌子（原 BUG-027 之 STEP12 部分）【证据 A】

**问题**
自测步骤 `12_翻桌与爆炸桶` 偶发 FAIL（约 1/250）：`玩家子弹击中了自己的掩体（应穿透）`。

**根因**
桌子的 +x 弹道上恰好有 barrel（hp=8）且该发 arc 子弹暴击时：
`7(dmg) × 2.5(暴击, weapons.js:117) = 17.5 > 8` → 一发打爆桶 → `build.js:848`
`G.weapons.explode(x,z,2.4,14,'any')` → explode 伤 props 的通道（weapons.js:199，`dist<r*.9`）
**不看 `table/flipped`** → 1.0 格外的翻倒桌子掉血 → 断言 FAIL。
桶位置与是否暴击都来自 `Math.random()`（BUG-022）。
注意：此前证伪过「桶在弹道」单条件（有桶的轮次照样 PASS）——单条件确实不充分，
必须与**暴击**组合才充分，这正是复现率低到 1/250 的原因。

**定向复现证据**（2026-09-02，不靠等随机）
强制 barrel 进弹道（`table.x+1.0`）+ 清空弹道其它 prop + `p.st.crit=1` → **6/6 FAIL**；
同一最坏场景下加修复 → **6/6 PASS**。

**当前解法**（`main.js` STEP12 断言前，2026-09-02）
把桌子 3.2 格内的 barrel 全部移到 `table.x-6, table.z+4`（斜后方 7.2 格）：
不在 +x 弹道上、距桌子 7.2 > 2.16（=2.4×0.9），即使爆炸也波及不到桌子。
STEP12 后半段的爆炸桶测试不受影响（仍能 `G.props.find` 到并引爆）。main v40。

**回归测试**
无独立回归锁（定向复现补丁为一次性验证工具，验证后已移除）；
根治判据 = 修复后大样本零失败。若未来给 STEP12 之前的流程加入可能产生爆炸的改动，须重新审视此条。

## FIX-026 · STEP44⑧ 自测 flake：残留红心磁吸回血，恰好抵消自爆伤害（原 BUG-027 之 STEP44⑧ 部分）【证据 A】

**问题**
自测步骤 `44_解锁系统与精英词缀` ⑧ 偶发 FAIL（约 1/250）：`爆裂自爆未伤及玩家: hp=6`。

**根因**
自爆伤害本身**同步且必然生效**：`G.hurtEnemy(sv,99999) → E.kill → explode(1.8,12,'e')`
→ 玩家伤害门（weapons.js:190）`!p.invulnT && p.rollT<=0`（两值刚被测试清零）→ `p.hurt(2)`，
hp 6→4。问题出在**断言等了 `uf(3)` 三帧**：④~⑦/clearAll 期间每次击杀有 2% 掉落红心
（enemies.js `E.kill`），当时玩家满血 → 红心冻结原地（player.js:811 `p.hp>=p.maxHp → continue`）；
⑧ 里 hp 被打到 4（<maxHp）→ 冻结的红心恢复磁吸追踪（magR=1.7），位于击退方向 0.8 格内的
心在 1~2 帧内被拾取 `heal(2)` → **hp 恰好被顶回 6** → 断言看到净伤害为 0。
爆炸 -2 与红心 +2 数值恰好相等，这是 FAIL 信息恒为 `hp=6` 的原因。
心的掉落与落点均来自 `Math.random()`（BUG-022），故复现率低且看似随机。

**定向复现证据**（2026-09-02，不靠等随机）
在 `clearAll()` 后于玩家 `p.x-0.55`（爆炸对侧=击退方向）强制放一颗红心 → **3/3 FAIL，
FAIL 信息与历史 flake 一字不差**（`hp=6`）。注意复现位置有讲究：放 `p.x+0.55`（爆炸同侧）
则 3/3 PASS——`p.hurt` 的击退（vx/vz=±5）把玩家踹离红心，3 帧磁吸追不上；
真实 flake 中红心恰好冻在击退方向时才会触发。

**当前解法**（`main.js` STEP44⑧，2026-09-02）
断言与帧后世界状态**解耦**（同 STEP43 的根治思路）：`sv.dead` 与 `p.hp` 均在
`G.hurtEnemy` 同步返回后立刻断言，`uf(3)` 移到断言之后（仅保留清理职责）。
对照实验：同一最坏场景（击退方向残留心）修复前 3/3 FAIL，修复后 3/3 PASS。main v41。

**回归测试**
断言已内置解耦（hp 在同步结算后读取），天然免疫帧后拾取干扰；
根治判据 = 修复后 30 轮大样本零失败。
